About the interrupt dispatch system. And about interrupts, to be honest.

Lots of interrupts being fired left and right, and everybody wants CPU attention - not to mention there's a hundred different ways to deal with them - handler this, handler that. In conclusion, we need one big manager to delegate tasks around - one that we can track to see what requests are coming in, and where they're going, and if they ever get completed. 

!abbrv - irq = interrupt request, handler = the functionality that takes care of these interrupt requests. 

This is implemented in a layer i'm calling (though I am not the first and will not be the last to call it that) the interrupt dispatch system. All irqs enter through one common function that decides what to call (which 'interrupt handler' to call). This function is in interruptDelegator.c and is called globalInterruptDelegator(context). This function uses the renowned interruptHandlerTable (a table with pointers to every handle for every irq) to jump the CPU to whichever specific handler is needed.
table[32] = ptr to handler num32
interrupt Delegator tells CPU to jump to that ptr and executes the code, thus dealing with the interrupt. 

1. Basic Structure: 
ASM ISR stub - global handler - delegation - specific handler

About the 'specific handlers'.
- every EXTERNAL irq must ping the CPU that it's done when it's been taken care of, lest the CPU get stuck in a perpetual state of trying to ping it. Internal IRQs are handled a bit different - no, don't ask, I forgot.
- All of them are defined in IRQHandler.c . I wanted to name that file IRQHandlers.c , but the naming convention Gods frowned upon me.


Example flow for IRQ0: (timer interrupt)

Hardware Timer
 → PIC (programmable interrupt chip)
 → Interrupt 32
 → IDT[32] (interrupt descriptor table. Hey, interrupts exist, and here's a list of them)
 → irq0 (idt.asm stub) (pushes the stack values which get saved in the cpu_CONTEXT, then calls the global interruptor)
 → globalInterruptDelegator(CPU_context)  (figures out which specific handler to call)
 → interruptHandlerTable[32]  (by checking the interruptHandlerTable, table[32] = ptr to the handler for number 32)( the ptrs in question are called 'gates' and work mostly the same as a normal pointer, except with a bit more information. )
 → irq0_Handler(context) (handles the interrupt request)(these are the specific handlers i was talking about)
