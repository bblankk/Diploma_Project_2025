The computer memory (ram, not rom)(that's the one that gets nuked when you close your pc) is divided into several different 'regions'. Think of the memory as a linear array, and you will not be too wrong. A range from some number (physical memory index) to another (another memory index) is generally called a region. Some regions can be used by your programs to run, some cannot. How do we know which is which?

Firstly , these regions are decided by the MANUFACTURER OF YOUR MOTHERBOARD. They're not malleable. Also may vary depending on your RAM. Thus , we read directly from the motherboard's chips, they give us that information (region information - which are usable , which will implode if you try, what this region's used for, etc.) on startup.
For each memory region type 1 (usable by programs!)(unusable regions cannot be overwritten, and thus not allocated) , there is a calibration of its':
- starting address
- ending address
Before passing it to the physical memory manager (lovingly called pmm) to use for it's own bookeeping (just keeping track of memory - used, running, not running, locked, returned, it's complicated). Manager it is, but it also allocates and deallocates memory. Programs make requests, and receive memory regions (from this to this memory, you can play here!) in turn. When they are done, they must return this 'playground' to the manager, who will give it to someone else. Some 'playgrounds' however, are privately owned by very rich kids. Mr. Manager is not allowed to give anyone else the rights to play there. These rich kids are usually the kernel and it's very IMPORTANT function friends (the whole system would crash if we dare rewrite (allocate) this memory). As such, only poor-people playgrounds are ever located by Mr. Manager. Thankfully, God (the motherboard) tells us directly who's poor or not, so now we allocate. Here is Mr. Manager's psyche:

The starting address of every allocable region needs to be made 'page-aligned' (pmm's bookeeping requirements), aka it is needs to be a multiple of 4096 (bytes)(that number may be different for different OSes, but it is 4096 here). This is because the physical memory only accepts memory in fixed-size 'pages' and refuses to chew arbitary blocks of data. This is just outdated hardware-mechanics (don't look at ME - I didn't vote for it!), there's not much that can be done but obeying the great hardware restrictions.
To do that, some math is involved.

If the region ends at a half-page, we need to discard the FIRST half of the page. We cannot move a page up, as we did with the base address, because this would be going into another region's territory, which is unacceptable, because that region could be an unusable memory region.
Of course, we'd loose some memory from the half-page, but it's certainly going to be less than 4096 bytes ( a page), and alas it's normal in memory management to sacrifice a few for the cause.
Memory management is closely related to utilitarian ethics, which judges actions based on whether they maximize overall happiness or welfare for the greatest number of people (memory).
